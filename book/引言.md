# 引言

## 安全从哪里开始

软件安全常被描述成一张很长的清单：密码、加密、漏洞、权限、日志、合规。清单有用，却很容易让人错过真正重要的问题：系统究竟在什么地方做了信任判断？它凭什么相信一个身份、一段数据或一次操作？这个判断失误时，谁会受到什么影响？

安全不是某个上线前的扫描步骤，也不是部署一个产品后就自动获得的属性。一个字段是否能被修改、一枚令牌何时失效、一个文件会被哪些服务复制、一次失败能否被发现并恢复，都是安全设计。开发者写下的每个接口、数据结构和默认配置，都在替系统向用户作出承诺。

本书从这些日常决定出发，帮助你建立一套可复用的判断方法。我们先描述要保护的资产和可能的损失，再沿着数据、身份和权限经过的路径寻找信任边界；接着理解密码学、认证、授权和输入验证各自能证明什么；最后把这些知识放回开发、部署、监控和恢复的完整生命周期中。

## 这本书写给谁

如果你已经能够读懂一个 Web 或 API 系统，接触过数据库、消息队列或部署流程，却没有系统学过安全，这本书就是为你准备的。你不需要先学会渗透测试，也不需要推导密码算法。你需要保持的是工程师的好奇心：面对一个“看起来安全”的方案，继续追问它的前提、边界和失败方式。

书中的例子会使用照片分享、协作工具、文件处理和多租户业务等常见场景。它们不是某个产品的设计方案，而是用来练习观察的缩小模型。阅读时，请把问题带回自己的系统：这条数据在哪里进入，谁能改变它，哪个组件最终作出决定，证据又在哪里留下？

## 如何阅读

本书可以顺序阅读，也可以按正在解决的问题查阅。第一部分建立安全语言：资产、威胁、风险和信任边界。第二部分解释不依赖深数学的密码学，帮助你分清随机数、哈希、加密、签名和证书的作用。第三部分进入 Web 中最常见的身份与访问边界。第四部分把这些基础知识用于输入处理、数据保护、安全开发、验证和事件响应。

每一章都尽量回答三个问题：一个机制解决了什么问题；它依赖哪些条件；哪些事情仍然没有被它解决。章节末尾的自检问题不是考试，而是提醒你把概念放回具体请求、资源和业务流程中。读完一章后，最好用自己的项目画出一条数据流，或者写下一条允许和一条拒绝的用例。

## 先带走一种习惯

遇到新的功能时，先不要急着寻找一个产品名称或一条万能配置。先问：需要保护什么？谁可能接近它？系统在哪里把外部输入当成了可信事实？当前控制实际证明了什么？如果控制失效，系统能否发现、限制影响并恢复？

这些问题不会替你做完架构设计，但会让讨论从“应该更安全一点”变成可以验证的工程判断。希望你读完这本书后，面对一个字段、一段协议或一次用户操作，都能看见它背后的安全假设，并知道下一步该用什么证据检验这些假设。
