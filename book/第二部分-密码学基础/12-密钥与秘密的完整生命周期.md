# 第 12 章　密钥与秘密的完整生命周期

> 章节概要：已明确本章范围与学习目标，完整正文和练习待扩写。

让密钥的生成、使用、轮换、撤销和恢复形成闭环。

## 场景与机制概要

证书可以公开，公钥也可以公开；真正需要严格保护的是私钥。私钥一旦被复制，密码学无法判断签名来自原主人还是窃取者。

因此，签名系统还需要工程控制：

- 限制能够调用私钥的主体和操作；
- 尽量减少私钥副本，明确备份与恢复规则；
- 对高价值密钥使用硬件保护或专门密钥服务；
- 记录签名和密钥管理操作，便于审计；
- 为泄露、人员变更和设备报废准备轮换与撤销流程；
- 将不同用途的密钥分开，避免同一把密钥同时承担服务认证、代码签名和其他高风险职责。

“签名可由第三方验证”有时会被描述为“不可否认”。这个说法不能脱离密钥管理使用。验证者最多证明某签名与某公钥匹配；要把签名归责到具体人员或组织，还要证明私钥控制、授权流程、时间记录和身份绑定都可信。

秘密与普通敏感数据的差别在于：泄漏的秘密往往能立刻授予能力。把 API Key 从源码移到环境变量，可以减少一种暴露，却没有解决谁能读环境变量、如何轮换、旧值何时失效、构建日志是否打印等问题。秘密管理应围绕身份、最小权限、短有效期、版本和审计展开。发现泄漏时，先停止旧值继续发挥作用，再清查历史副本和异常使用；只删除文件中的那一行无法撤回已经复制出去的秘密。
