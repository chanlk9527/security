# 第二部分导读：密码学原理与工程实践

密码学不是一串彼此孤立的算法名称，而是一套围绕数据、身份和密钥建立安全保证的工具。理解密码学，首先要看清不同机制分别解决什么问题、依赖什么前提，以及它们如何组合成协议。

本部分先建立这张全局地图，再分别讨论随机数、哈希、认证加密、公钥机制、数字签名、证书、TLS 和密钥生命周期。阅读时始终区分三个问题：系统要保护什么，哪种机制提供这种保证，以及这种保证在哪个边界停止。

## 密码学主要在保证什么

密码学机制通常围绕几类目标展开：

- **不可预测性**：别人猜不到 Token、Nonce 或密钥。
- **完整性**：数据被修改后能够被发现。
- **保密性**：没有密钥的人无法读懂内容。
- **来源真实性**：能够确认消息来自某个密钥持有者。
- **密钥建立与信任**：双方如何建立共享密钥，以及为什么相信某个公钥。
- **生命周期控制**：密钥如何生成、使用、轮换、撤销和恢复。

这些目标有关联，但不能互相替代。加密主要解决保密性；哈希主要提供摘要和结构基础；MAC 和认证加密依赖共享密钥来发现篡改；数字签名使用私钥签名、公钥验证；证书和信任配置进一步回答“这个公钥属于谁”。

## 从基础工具到安全协议

可以把本部分看成一条从底层工具走向工程协议的路径：

```text
随机数、秘密、Nonce
        ↓
哈希、KDF、密码存储
        ↓
MAC、对称加密、认证加密
        ↓
公钥加密、密钥交换、数字签名
        ↓
证书、公钥信任、TLS
        ↓
密钥轮换、撤销、恢复与迁移
```

这条路径不表示所有机制都必须按单一顺序组合，而是帮助读者理解它们各自承担的角色：

- 随机数和秘密提供不可预测的基础材料；
- 哈希、密钥派生函数和密码存储把输入转换成适合特定用途的记录；
- 对称机制高效保护数据，并检查数据是否被修改；
- 公钥机制解决没有预共享秘密时的密钥建立问题；
- 数字签名证明某个密钥持有者对确定内容作出承诺；
- 证书和信任链把公钥与名称、用途和验证范围联系起来；
- TLS 将这些机制组合成一条有明确边界的安全通道；
- 密钥生命周期处理生成、使用、轮换、泄露、撤销和恢复。

## 几条必须分清的边界

密码学最容易被误用的地方，往往是把一种保证当成了另一种保证：

- **加密不等于身份认证**。能解密内容，不代表已经确认发送者身份。
- **哈希不等于密码存储方案**。密码存储还需要专门抵抗离线猜测的算法、盐和参数管理。
- **签名不自动证明业务身份真实**。签名首先证明某个私钥持有者签过确定的字节。
- **证书不自动授予业务权限**。证书建立公钥归属，授权仍由应用规则决定。
- **TLS 不会保护所有处理环节**。它保护连接覆盖的范围，连接终止后的数据处理仍需要其他控制。
- **算法安全不等于密钥管理安全**。密钥的保存、权限、轮换和泄露处置同样决定最终结果。

## 读完本部分后应能回答什么

- 一个功能需要保密性、完整性、来源真实性，还是密钥建立？
- 为什么这个目标需要当前机制，而不能用看似相近的另一种机制替代？
- 机制依赖哪些密钥、随机值、参数和信任前提？
- 数据经过哪些组件，保护在哪一步开始、在哪一步结束？
- 密钥泄露、算法升级或信任撤销后，系统怎样继续运行并完成恢复？

读者最终应能画出加密、签名、证书和 TLS 的关系，说明每个密钥的用途与生命周期，并为一个具体功能写出密码机制的保证、前提和失败行为。各章的当前状态和后续扩写范围见[全书大纲与定位](../全书大纲与定位.md)。
