# 第一部分导读：安全问题怎样被描述

安全设计经常从技术名词开始：要不要加密、要不要上 WAF、要不要换一种令牌。这样的讨论容易把手段当成目标，也容易遗漏真正的损失。本部分先把问题说清楚，再进入密码学、身份和开发运行控制。

## 本部分要建立的判断

读完本部分，你应当能够回答：

- 系统中哪些东西值得保护，损失是泄漏、篡改、不可用、冒用还是超出约定用途；
- 哪些人、程序、第三方和后台任务能够接近这些东西；
- 数据、身份和控制指令跨过哪些边界，哪里发生了信任变化；
- 一个安全控制实际证明了什么，哪些问题仍然需要其他控制；
- 一条风险如何被改写成攻击故事、控制措施、验证证据和剩余风险的决定。

## 建议的阅读方式

先拿一个自己熟悉的功能，例如“用户上传文件并邀请同事查看”，不要急着列漏洞名称。写下它要保护的资产、可能造成的损失、参与的主体和数据经过的组件，再阅读本部分。读完后回头检查：你是否能把“这里要更安全”改写成一条可以测试或审计的要求。

本部分的产出不是一张看起来完整的架构图，而是一份足以开始评审的最小问题清单。后续章节会分别补充密码学、认证、授权、输入验证和运营响应等控制。
