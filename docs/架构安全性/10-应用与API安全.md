# 应用、API 与业务安全

> 返回《[架构安全性](00-架构安全性总览.md)》目录。本文是现代扩展。输入解析见[验证](09-验证.md)，身份与权限模型见[认证](02-认证.md)和[授权](03-授权.md)。

假设系统提供一个查询订单的接口：`GET /orders/1001`。用户已经登录，请求参数也是合法整数，数据库查询使用了参数化语句，一切看起来都符合安全编码要求。可当用户把 `1001` 改成 `1002`，却看到了别人的订单。

这类问题在 OWASP API Security 中被称为对象级授权缺失，常见名称还有 BOLA 或 IDOR。它说明认证和输入验证都通过，并不代表业务操作就是安全的。API 安全真正需要判断的是：这个主体能否访问这个对象、能否修改这些字段、当前状态能否执行这个动作，以及执行的规模是否合理。

## 标识符不是权限

一些系统用随机 UUID 代替连续数字，认为攻击者猜不到 ID 就无法越权。随机标识确实降低了枚举效率，却没有建立访问控制。ID 可能从日志、分享链接、Referer、客服截图或其他接口中泄漏，一旦得到，服务端仍然需要判断它与当前主体的关系。

对象级授权必须在真正了解资源的服务中完成。网关可以验证令牌和粗粒度角色，却通常不知道订单属于谁、文档是否已经共享、设备是否已经转让。详情接口需要检查，列表、搜索、统计、导出和异步任务也要使用同一资源范围；否则攻击者不必逐个读取，只需寻找一个忘记加过滤条件的批量入口。

字段也有权限。更新个人资料时，如果框架直接把整个 JSON 绑定到数据库对象，攻击者可能额外提交 `role=admin`、`ownerId=...` 或内部状态。业界称之为批量赋值问题，解决办法不是建立一份“危险字段黑名单”，而是为每个动作定义明确的输入模型，只接收该场景允许修改的字段。

## API 契约为何也是安全边界

接口契约不仅方便生成文档，它还能限制攻击者可供组合的空间。请求允许哪些内容类型、字段、长度、分页、排序和过滤条件，响应会暴露哪些属性，都应当是明确的。未知字段如果被静默忽略，今天看起来没有影响，明天某个新版本恰好开始解释它，就可能产生跨版本行为差异。

系统还应知道自己有哪些 API。对外接口通常有人维护，内部接口、管理接口、旧版本、GraphQL、WebSocket、消息消费者和临时调试入口则容易成为“影子 API”。调用量下降不等于已经下线，安全修复只有在最后一个入口关闭后才算完成。管理面尤其不应只是普通接口加一个隐藏路径，它需要独立的强身份、网络入口和审计边界。

## 一笔钱为什么不能只校验一次

考虑支付流程：创建订单、确认金额、发起支付、接收回调、完成发货。每个请求单独看都可能合法，攻击者却会尝试跳过步骤、重复回调、并发确认或让延迟消息把状态推回过去。这类问题无法用字符串校验解决，因为错误发生在多个合法动作的组合上。

解决方法是把业务流程建模为状态机，明确哪些迁移允许发生，并把关键不变量放在持久化边界最终校验。幂等键和唯一业务号防止重试造成重复执行，版本号或条件更新防止两个并发请求同时基于旧状态成功。签名回调还要绑定方法、路径、正文摘要、时间戳和唯一消息 ID；签名只能证明消息来自某个密钥持有者，不能证明同一条合法消息没有被重放。

异步消息同样如此。实际消息系统普遍更接近“至少投递一次”，消费者必须能识别重复，说明对顺序的假设，并处理延迟、死信和补偿。把安全不变量寄托在“这条消息应该只来一次”，通常会在网络第一次抖动时破产。

## 合法功能也能被用来攻击

搜索、注册、发送验证码、导出报表和调用大模型都是合法能力，一个合法账号却可以把它们调用十万次。只按 IP 限流并不可靠，移动网络会让大量用户共享地址，攻击者又能轻易更换代理。限额需要结合账号、租户、设备、来源、资源和真实成本。

这里的“成本”比请求次数更重要。一条复杂 GraphQL 查询、一次压缩包解析或一次长上下文模型调用，可能比普通请求昂贵几个数量级。系统要限制正文、分页、递归、并发、执行时间、响应大小和下游调用预算，并通过排队和背压防止入口的一点流量放大为数据库与第三方服务的全面饱和。

优惠套利、批量注册、刷量和爬取则属于业务滥用。攻击者没有绕过任何技术规则，而是在规则允许的空间中寻找规模优势。应对它们往往需要风险检测、速度摩擦、业务限额和人工复核，而不是再增加一个“是否登录”的判断。

## 客户端从来不是可信执行环境

前端隐藏按钮、移动端检测 Root、桌面程序混淆代码都能增加攻击成本，却不能决定最终权限。客户端运行在用户控制的设备上，请求可以被重放和修改，内置的共享 API Key 也迟早能够被提取。服务端必须重新判断身份、对象、字段、状态与成本。

浏览器还有自己的安全模型。`HttpOnly` Cookie 能阻止脚本直接读取会话，却需要处理 CSRF；CORS 决定哪些网页能读取跨域响应，却不是服务端授权；CSP 能限制脚本来源和注入后的影响，却不能修复错误的输出编码。移动端则要关注深链、通知、剪贴板、截图、调试日志和本地备份对令牌及敏感数据的暴露。平台安全存储适合保存每个安装实例独有的密钥，不适合藏一份所有客户端共用的永久秘密。

安全的 API 最终不是拥有最多中间件的 API，而是每条路径都能清楚回答：谁以什么身份，在什么业务状态下，对哪项资源做了什么；系统为何允许，失败后又如何限制影响。
