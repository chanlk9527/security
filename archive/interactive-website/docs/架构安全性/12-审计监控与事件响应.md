# 审计、检测、事件响应与恢复

> 返回《[架构安全性](00-架构安全性总览.md)》目录。本文是现代扩展，讨论预防控制失效以后，系统如何发现攻击、限制影响并恢复可信状态。

某天凌晨，一名管理员在十分钟内导出了几十万条用户记录。每次请求都通过了 MFA，令牌签名正确，账号也确实拥有导出权限。系统没有抛出任何异常，数据却已经离开了边界。

这类事件揭示了预防控制的极限。认证能够证明凭证有效，授权能够证明操作在静态规则内，却不能证明此刻的行为符合账号所有者的真实意图。系统必须具备第二条防线：记录足以重建事件的证据，从行为中发现偏离，并在确认失陷后快速撤销权力。

## 记录什么才算审计

普通应用日志关注程序是否正常运行，审计日志关注谁改变了系统中的安全事实。登录与账号恢复，认证器变更，角色和组织关系变化，管理员查看敏感数据，令牌、证书和密钥的签发与撤销，构建、发布、回滚以及安全策略变化，都属于需要追责的事件。

一条有用的审计记录至少能回答：可信时间是什么，主体是谁、通过哪种身份来源，操作了什么资源，做了什么动作，结果如何，来自哪里，使用哪个策略版本，以及它与上下游哪些请求属于同一次行为。关联 ID 可以沿调用链传播，但主体不能直接相信客户端传来的 Header，否则攻击者连自己的审计身份也能伪造。

记录越多不一定越好。密码、验证码、私钥、完整 Token、签名下载地址进入日志，会把调查系统变成新的泄漏源；手机号、邮箱和请求正文无差别保存，也会扩大隐私风险。常见做法是记录内部标识和必要元数据，高敏内容按独立审批临时读取。关键审计存储与业务管理员分离，并保护完整性，使入侵者不能在修改数据之后顺手删除证据。

## 从日志查询到检测工程

“我们有日志，出事后可以查”仍然是一种被动能力。真正的检测要从威胁模型反推可观察信号。账号接管可能表现为异常恢复、认证器新增、Refresh Token 重用和跨地域会话；数据泄漏可能表现为对象枚举、非工作时间查询与导出规模突增；工作负载失陷可能表现为新进程、提权、异常出站和秘密集中读取；供应链攻击则可能表现为未知制品、签名失败或生产部署与版本库不一致。

单个信号通常都有合法解释。员工可能出差，批量导出也可能是年终审计。因此检测不是写下一条阈值便结束，而要定义数据来源、基线、严重级别、调查步骤和升级路径，再用攻击模拟或历史事件验证规则确实能够触发。没有负责人和处置动作的告警，只是比普通日志更昂贵的噪声。

自动响应也要克制。发现疑似撞库后冻结账号可以止损，攻击者也可能故意对大量用户名制造失败登录，借系统之手拒绝合法用户。自动隔离适合边界明确、可逆且高置信度的动作；大范围吊销和停服需要人工接管，并准备恢复路径。

## 为什么换一枚密钥还不算响应完成

以 JWT 签名私钥泄漏为例，立即生成新密钥只是第一步。团队还要停止信任旧公钥，确认哪些系统接受过它，判断攻击者可能伪造哪些令牌，撤销相关会话，寻找异常使用，并决定在旧令牌最长有效期内采取什么限制。如果同一把密钥还被用于其他签名，影响面会继续扩大。

完整的事件响应通常沿着准备、确认、控制、清除、恢复和复盘推进。确认阶段建立时间线与影响范围；控制阶段隔离账号、服务、设备或供应链通道；清除阶段修复入口并移除持久化；恢复阶段从可信制品和数据逐步恢复流量。对外沟通则依据合同、法规和实际影响进行，既不能在事实不清时过度承诺，也不能因为技术服务已经恢复就忽略用户风险。

“重装一台服务器”未必恢复了可信状态。如果构建系统已失陷，新装的仍可能是恶意制品；如果身份提供方失陷，攻击者可能再次登录；如果日志已被删除，团队甚至不知道持久化入口在哪里。恢复必须同时验证身份、密钥、配置、制品、数据和外部依赖。

## 备份为什么不等于可恢复

勒索和误删除同时威胁可用性与完整性。生产管理员如果也能删除所有备份，攻击者取得这个账号后就能一次摧毁在线数据和恢复能力。备份需要与生产身份和删除权限隔离，保留不可变或离线恢复点，并定期执行完整恢复。

恢复演练不能止于“数据库文件能够还原”。系统还需要匹配的配置、密钥、制品、DNS、证书和第三方依赖，恢复后的数据要满足业务不变量，审计与监控也要同步工作。架构应为关键业务定义可接受的中断时间和数据丢失量，再验证依赖链是否真的满足，而不是把 RTO、RPO 写在文档里。

限流、排队、背压、熔断和资源配额则负责在攻击或故障发生时控制成本传播。身份、密钥、DNS、时间和控制面这些公共依赖一旦不可用，系统是拒绝敏感操作、进入只读模式还是排队等待，都应提前决定。灾难切换不能以“紧急”为由绕过认证、加密和审计，否则备用环境会成为攻击者期待已久的低门槛入口。

一次事件真正结束的标志不是服务重新变绿，而是团队理解了控制为何失效、为何没有及时发现，并把这个答案变成新的架构约束、检测和演练。
