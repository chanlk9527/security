# 安全开发、供应链与运行平台

> 返回《[架构安全性](00-架构安全性总览.md)》目录。本文是现代扩展，讨论源码如何变成生产中运行的制品，以及这条链路如何保持可信。

某个项目的源码经过严格评审，没有发现恶意代码。上线后的容器里却多出一个窃取环境变量的程序。调查发现，攻击者没有修改业务仓库，而是取得了构建平台权限，在打包阶段替换了一个依赖。源码是干净的，生产制品却不是那份源码构建出来的。

这类事件改变了安全开发的关注范围。我们不再只问“代码有没有漏洞”，还要问“依赖从哪里来、谁完成构建、制品是否被替换、部署策略是否被绕过，以及运行平台会不会把一个容器的失陷扩散成整个集群的失陷”。

## 从开发检查到制品信任链

传统流程习惯在上线前运行 SAST 和依赖扫描，再把报告交给安全团队。扫描能发现一部分已知问题，却不能证明生产中运行的二进制就是被扫描的那一份，也不能证明构建时没有下载另一个同名包。

现代供应链安全更像现实世界的物流追踪。依赖要来自受控仓库，版本被锁定并校验摘要；构建任务记录源码版本、构建器、参数和依赖，生成可验证的来源证明；完成的制品被签名，部署平台只接受满足来源策略的制品。这样做并不保证软件没有漏洞，却保证“此刻运行的东西确实来自我们批准的那条生产链路”。

SBOM 是这条链路的货物清单。新的组件漏洞披露后，团队可以反查哪些线上制品包含受影响版本，而不是挨个询问项目。它仍然不是安全评分：列出某个库不代表漏洞一定可达，没有列出恶意构建步骤也不代表构建可信。SBOM、来源证明和制品签名分别回答“里面有什么”“怎么产生的”和“是否被替换”，三者解决的是不同问题。

## 构建系统为何比生产服务器更值得保护

构建平台通常能读取多个仓库、获取包依赖、签名制品并部署到生产，它掌握的权限可能比任何一台业务服务器都大。更危险的是，开发者往往允许来自 Pull Request 的代码直接在 CI 中运行。如果这类不可信代码能够读取生产 Secret，攻击者甚至不必让恶意修改通过评审，只需在测试脚本中把凭证发送出去。

所以，不可信分支的构建环境不能获得生产秘密和发布权限；构建执行器应短生命周期、权限与网络受限，不在不同信任级别任务之间保留状态。仓库、包仓库、CI/CD 和发布平台的高权限账号使用抗钓鱼认证，敏感工作流变化由明确的代码所有者复核。发布权限最好由工作流身份按任务临时获得，而不是放一枚长期云密钥在 CI 配置中。

依赖安装本身也会执行代码。依赖混淆利用内部包名与公共仓库冲突，拼写抢注利用开发者的一次输入错误，安装脚本则可能在构建开始前就取得执行权。锁定版本、限定来源、校验完整性和隔离安装阶段，比只在构建结束后扫描文件更靠近问题根源。

## 基础设施为何也属于软件

业务代码没有给数据库开放公网端口，云控制台的一次手工点击却可以做到；应用没有授予容器特权，一份部署清单却可以挂载宿主机。基础设施即代码（IaC）的意义不只是提高运维效率，也是把网络、身份、存储和运行权限带回版本控制、评审与测试。

生产云账号、集群和管理面应与开发环境隔离。人员通过联合身份和临时提权操作，工作负载使用短期平台身份。控制台紧急修改并非绝对禁止，但必须留下审计并回写声明配置，否则真实环境与版本库之间的漂移会逐渐形成无人理解的安全例外。

## 容器边界有多坚固

容器带来了便捷的进程隔离，但命名空间并不是虚拟机那样的完整安全边界。一个以特权模式运行、挂载宿主机套接字的容器，几乎等于获得了节点控制权。常规工作负载应以非特权用户运行，只保留必要的系统能力，使用只读根文件系统，并限制网络出口和资源。准入策略可以在部署前拒绝来源未知、签名无效或权限过大的镜像。

同一个集群中的不同命名空间适合隔离合作团队，却未必适合承载彼此敌对的租户。租户价值越高、彼此信任越低，就越有理由使用独立集群、云账号、虚拟机或专用沙箱，并分离密钥与网络。隔离从来不是越强越好，它以成本和运维复杂度换取更小的爆炸半径。

服务网格可以统一工作负载 mTLS 和网络策略，却不知道“这位用户是否能修改这张订单”；运行时检测可以发现异常进程，却不能替代应用的对象授权。平台控制与业务控制各自守住不同边界，才是真正的纵深防御。

## 漏洞报告怎样变成风险治理

扫描器会产生大量结果，CVSS 最高的问题却未必是最先能被攻击的那个。一个只在构建期使用、从不处理不可信输入的库，与一个直接暴露公网且已有利用代码的组件，修复优先级显然不同。漏洞治理要结合可达性、暴露面、资产价值、现有攻击和补偿控制。

这并不是给延期寻找借口。每项延期都应有临时缓解、风险承担人、到期时间和退出计划；修复后还要回归并排查同类代码。SAST、SCA、秘密扫描、IaC 检查、模糊测试和渗透测试都是发现问题的手段，真正的安全开发闭环，是让发现的问题进入版本、责任和验证，而不是让流水线永久亮着一片无人理会的黄色警告。
