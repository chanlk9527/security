# 安全架构基线检查表

> 返回《[架构安全性](00-架构安全性总览.md)》目录。本文是现代扩展，用于架构评审、上线门禁和定期复查。每个“已完成”都应链接到配置、测试、查询或演练证据；不适用项需要写明理由。

这份表只检查控制是否形成闭环，具体做法以对应章节为准。项目应先按[威胁建模](01-威胁建模与安全原则.md)确定风险，再裁剪控制，不能把清单当成无需判断的合规模板。

## 风险与边界

- [ ] 已识别业务资产、数据、主体、外部依赖、数据流与管理面。
- [ ] 已标明互联网、终端、租户、环境、云账号、集群、第三方等信任边界。
- [ ] 已覆盖外部攻击、内部越权、供应链、业务滥用、资源耗尽和恢复失败场景。
- [ ] 高风险有负责人、期限、验收方法和剩余风险接受人。
- [ ] 架构或数据用途变化能够触发威胁模型复查。

## 身份、权限与凭证

- [ ] 用户、管理员、工作负载、第三方和设备身份分别建模，不共享高权限账号。
- [ ] 管理员和高价值操作使用抗钓鱼 MFA，并设计安全的账号恢复与重新认证。
- [ ] OAuth/OIDC 使用适当的现代流程并完整校验签发方、受众、回调、PKCE、state/nonce。
- [ ] 权限矩阵覆盖主体、资源、动作、条件、拒绝用例与跨租户访问。
- [ ] 资源服务执行最终对象级授权，列表、导出、后台和异步路径没有旁路。
- [ ] Session、Cookie、JWT 和 Refresh Token 有明确有效期、轮换、撤销和泄露检测。
- [ ] 人员离职、成员移除、资源转移和账号冻结会传播到会话、缓存和下游授权。

## 数据、密钥与通信

- [ ] 数据清单包含分级、目的、位置、接收方、保留期、备份和删除方式。
- [ ] 收集、共享、分析、AI 使用和导出符合最小化与目的限制。
- [ ] 敏感数据在传输、存储、日志、消息、备份和终端副本中受到相应保护。
- [ ] 秘密不进入源码、镜像、普通配置和日志；工作负载优先使用短期身份。
- [ ] 密钥按用途、环境和信任域隔离，具备版本、轮换、撤销与紧急处置方案。
- [ ] TLS、证书、服务间身份及非 HTTP 链路已按当前平台安全基线验证。
- [ ] 已规划密码学算法迁移，不允许调用方通过输入降级算法。

## 应用、API 与业务

- [ ] 对外、内部、管理、历史 API 和消息接口有清单、所有者及下线计划。
- [ ] 所有不可信输入按类型、边界和业务状态校验，输出按上下文编码。
- [ ] SQL、命令、模板、反序列化、SSRF、文件与富文本采用专门控制。
- [ ] 对象、字段、函数和批量操作执行服务端授权，客户端声明不作为信任依据。
- [ ] 关键流程具有状态机、不变量、幂等、防重放和并发控制。
- [ ] 登录、搜索、上传、导出、高成本查询和第三方调用按成本限额并监控滥用。
- [ ] Web、移动端、Webhook 和第三方集成的凭证、跨域、本地存储与回调边界已验证。

## 软件供应链与运行平台

- [ ] 仓库、CI/CD、包仓库和发布平台使用强身份、最小权限、分支保护与变更审计。
- [ ] 不可信构建不接触生产秘密；构建器隔离且使用短期凭证。
- [ ] 依赖锁定并校验来源，线上制品可追溯到源码、构建记录、签名和 SBOM。
- [ ] SAST、SCA、秘密、IaC、镜像和针对性安全测试有缺陷闭环，而非只生成报告。
- [ ] 云账号、环境、控制面和管理入口隔离；IaC 漂移和控制台紧急变更可发现。
- [ ] 容器/工作负载采用非特权、最小能力、网络与资源限制；高风险租户使用更强隔离。
- [ ] 漏洞优先级结合可利用性和资产，具有修复时限、缓解、例外到期和复查。

## 审计、响应与恢复

- [ ] 认证、授权、数据、密钥、构建、部署和控制面关键事件能够关联查询。
- [ ] 日志不含秘密和无必要的个人信息，关键审计存储与业务管理员分离。
- [ ] 检测覆盖账号接管、越权泄露、工作负载失陷、供应链和防御规避，并已验证触发。
- [ ] 每条高优先级告警有负责人、调查步骤、自动化边界和升级路径。
- [ ] 事件响应能隔离主体与工作负载，批量撤销 Session、Token、证书和密钥。
- [ ] 备份与生产删除权限隔离，并能从可信制品、配置、密钥和数据恢复完整系统。
- [ ] 已按恢复目标演练账号接管、密钥泄露、数据泄露、供应链替换、勒索或关键依赖故障。

## 条件性场景

- [ ] 若有 IoT、嵌入式或边缘终端，已按[设备身份与设备安全](13-设备身份与设备安全.md)完成生产、注册、运行、更新和退役全链路评审。
- [ ] 若有模型、RAG 或 Agent，已按[AI 与 Agent 系统安全](15-AI系统安全.md)评审提示注入、检索权限、工具调用、数据边界和模型供应链。
- [ ] 若系统涉及支付、健康、工业控制、未成年人或其他受监管高风险领域，已增加领域法规和人身安全要求。

## 上线结论

评审结论应是“在指定版本和环境中，哪些风险已由什么证据降低，哪些风险由谁接受到何时”，而不是简单的通过或不通过。上线后出现新资产、新攻击路径、重大漏洞或控制失效时，应重新打开相关结论。
